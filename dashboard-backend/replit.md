# Sales Analytics Dashboard

## Overview

This AI-powered sales analytics dashboard analyzes sales conversation transcripts using OpenAI's GPT-5 to extract insights on customer needs, satisfaction, competition, and value proposition opportunities. It allows users to upload transcripts and strategy documents, then visualizes trends through interactive dashboards with charts and metrics. The system provides both strategic and operational analytics, including PICA performance, deal health, and DMU insights, aiming to offer action-oriented steering enhancements for management and sales teams.

## User Preferences

Preferred communication style: Simple, everyday language.

## System Architecture

### Frontend Architecture

**Framework**: React with TypeScript (Vite).
**UI**: shadcn/ui (Radix UI, Tailwind CSS).
**Routing**: wouter.
**State Management**: React Query (server state), React Context API (internationalization), React hooks (local state).
**Styling**: Tailwind CSS with custom design tokens, dark mode, custom elevation system, Inter and JetBrains Mono fonts.
**Design**: Component-based architecture with reusable UI components and separation of concerns.

### Backend Architecture

**Framework**: Express.js with TypeScript.
**API**: RESTful endpoints for transcripts, strategy documents, and aggregated analytics.
**Data Processing**: Asynchronous analysis of uploaded transcripts using OpenAI API, with results stored in the database.
**Storage**: Abstracted storage interface, with Drizzle ORM for PostgreSQL.
**Key Decisions**: Modular design, asynchronous processing, separate storage for strategy documents.

### Database Schema

**ORM**: Drizzle ORM for PostgreSQL (Replit built-in, via `pg` pool + `drizzle-orm/node-postgres`).
**Tables**: `users` (authentication), `transcripts` (conversation data, analysis, status), `strategyDocuments` (reference content), `companies`, `sessions`.
**Schema Design**: UUID primary keys, JSON text for analysis results, status field for processing tracking.

### Authentication System

**Features**: Email/password login, session-based authentication, TOTP-based 2FA, role-based access control (`superadmin`, `admin`, `user`).
**Superadmin Features**: Company and user management, 2FA status overview.
**API Endpoints**: Comprehensive set for authentication, 2FA management, and user/company administration.
**Schema Extensions**: `companies` table, `users` table extended with `email`, `phone`, `mobile`, `companyId`, `role`, `twoFactorSecret`, `twoFactorEnabled`.

### Analytics System

**Cumulative Snapshots**: Weekly analytics snapshots (YYYY-WXX:dashboardType:language) accumulate data, enabling trend analysis. Supports date filtering by year and month. Snapshot writes are serialized via `queueSnapshotUpdate()` (promise-chain per snapshot key) to prevent race conditions when multiple transcripts are uploaded in parallel.
**Operational Analytics**: Extended OpenAI analysis to extract metrics like PICA Performance, Deal Health, Resistance & Needs, Next Step Discipline, and DMU Insights.
**AI Prompt Architecture**: Two sets of prompts (Strategic and Operational) in 6 languages, featuring speaker recognition, implicit signal detection, and scoring guidelines.
**Action-Oriented Steering**: Upgraded `PieChartCard` with trend indicators, priority badges, alerts, and summaries. `ConclusionCard` now has 5 structured sections: `observation`, `cause`, `operational`, `strategic`, `action`. Role-based action blocks (Management, Sales Manager, Team) are generated by the AI.
**Priority Scoring**: Enhanced `computePriority()` with frequency, trend, and impact scores, and urgency counter badges.
**phaseDetails Feature**: Replaced `subskillScores` with `phaseDetails` — a structured array of 4 phases (1=Proposition, 2=Investigation, 3=Convincing, 4=Agreement), each with per-criterion metrics (15 total: breakTheIce, salesPitch, goalQuestion, expectationMgt, contactPerson, company, cooperation, consequences, cure, deepQuestioning, customerType, uspUbrLink, result, acknowledgement, agreement). `PicaPerformanceDashboard` shows 4 phase tiles with colored progress bars per metric. All 6 language OpenAI prompts updated. Demo data in all 6 languages uses `phaseDetails`. Merged via `mergePhaseDetails()` helper.

### Per-Company Data Isolation

**Option 1 implemented**: Each company's data is isolated via a `companyId` column on all data tables (`transcripts`, `strategy_documents`, `plan_documents`, `analytics_snapshots`).
- **Superadmin** (`role = 'superadmin'`, `companyId = null`): sees all data across all companies, no filter applied.
- **Regular users** (`role = 'admin'|'user'`): only see data where `companyId` matches their own company.
- `getCompanyFilter(req)` helper in `routes.ts` returns `undefined` for superadmin (no DB filter) or the user's `companyId` string for filtering.
- Session stores `companyId` and `userRole` at login and 2FA-verify time.
- Plan documents fall back to global plan (null `companyId`) if no company-specific plan exists.
- AssemblyAI webhook accepts `?companyId=` query param to assign transcripts to a specific company.
- Snapshot queue keys include `companyId` prefix: `${companyId ?? 'global'}:${weekNumber}:${dashboardType}:${language}`.

### Brandkit Feature

Allows company logo upload for PDF reports via Admin Dashboard. Logos are stored in Replit Object Storage and embedded into generated PDF reports.

### GPT-5 Reasoning Model Notes

GPT-5 is an o-series reasoning model: `temperature` parameter is not supported (must be omitted). Internal reasoning tokens count against `max_completion_tokens`, so values must be set high enough to allow both reasoning and output. Current values: tile-chat and tile-conclusion use 8000 tokens; management-conclusion uses 16000 tokens; `analyzeTranscript` (strategic) and `analyzeTranscriptOperational` (operational) both use 16000 tokens. The `response_format: { type: "json_object" }` must use **fixed English JSON keys** in the prompt (AI writes values in the target language) to avoid key-mapping issues across languages.

### ManagementConclusionCard Integration

`ManagementConclusionCard` is integrated into `ResistanceNeedsDashboard` (Operational > Resistance & Needs). Two cards appear below the pie charts: one for resistances (type: "weerstanden") and one for commercial triggers (type: "triggers"). Cards only render when demo data is present. Uses `toEnrichedItems()` helper to convert chart data to `EnrichedInsightItem[]` format.
